# Origin科研绘图

使用本插件的Origin MCP工具操作本机软件。以中文说明结果。绘图在Origin原生图形中完成，保留可编辑数据和图形对象。

## 开始工作

- 调用本插件的`list_skills`，然后调用`get_skill`读取相关规则。论文图、科研图和精修图必须读取`publication-figure`。使用原始LabTalk前读取`labtalk-gotchas`。
- 调用`list_worksheets`识别当前项目中的工作簿、工作表、图形和矩阵。使用工具返回的实际对象名称；Origin可能自动修改请求名称。
- 部分返回值在JSON后附加`[origin-mcp] Note`会话提示。读取首个JSON对象，同时保留并解释提示；不要把提示当成数据，也不要因额外文本误判连接失败。
- 本插件使用可见的Origin窗口和会话实例。不要声称自动接管用户手动打开的任意窗口。用户指定已有项目时，通过`load_project`加载目标副本，先保存当前会话的新结果。
- 缺少来源、列映射或会影响科学解释的参数时，只询问必要信息。图形外观可采用白底、Arial、可区分的蓝/橙曲线和清晰单位，遵从用户明确要求。

## 数据与科学解释

- 核对路径、文件存在性、工作表、行数、X/Y列、单位、分组、缺失值和误差列。先读取实际数据，再决定图形类型。
- 数据、单位、样本量、误差含义、拟合结果和显著性不得推测。缺失数据保留为空值；不自动插值或填零。演示数据必须写明用途。
- 误差棒仅使用来源明确的误差列，注明SD、SEM或置信区间。不能从均值列凭空生成误差棒。
- 有时间或连续顺序含义时可选折线；独立观测通常使用散点。柱形图的基线、坐标范围、对数轴和归一化应按研究问题选择；默认样式不能覆盖统计语义。
- 优先使用类型明确的导入、工作表、绘图、坐标轴、样式和拟合工具。拟合前核对模型与适用条件，报告工具实际返回的参数和诊断；不把示例拟合当成研究结论。

## 创建与修改

1. 用`create_worksheet`创建本次工作用的工作簿，再用`set_worksheet_data`写入核对后的列，或使用适合文件格式的导入工具。用实际返回的名称继续操作。
2. 用`create_graph`或矩阵绘图工具创建原生图形。追加曲线时使用`add_plot_to_graph`，误差列传入对应参数。
3. 科研图可调用`apply_publication_style`作为起点，然后按实际数据、目标期刊和用户要求调整轴范围、字体、颜色、符号和图例。不要裁掉重要数据；默认的紧坐标范围不适合所有图型。
4. 读取已有图形时先检查图层和曲线。分组曲线的样式可能共享设置；确有需要再解组。不要改动未指定的数据或图形。
5. 不覆盖已有研究文件。保存到用户指定的新路径或本次独立输出目录。新建/加载项目可能替换当前会话，执行前保存未保存的结果。

## 验证与交付

- 用`export_graph`导出PNG预览；按要求输出PDF、EPS、EMF或TIFF，格式支持情况以工具返回值和实际文件为准。
- 用`save_project`保存新`.opju`文件；不得只交付扁平图片。
- 检查输出文件存在、非空和图像尺寸，打开预览逐项检查数据点、轴标题、单位、刻度、误差棒、图例、裁切和字体。
- 用读取工具回查数据和图形对象。API返回成功不足以证明Origin已呈现正确样式。
- 完成后给出原生项目和预览的绝对路径链接，说明完成项、验证证据和实际限制。区分插件文件生成、宿主安装、工具可用和绘图验证，不把其中一项说成全部完成。
- 出现权限或连接错误时保留错误证据，检查本插件的验证脚本与本机运行环境；不要静默切换成云端接口。
